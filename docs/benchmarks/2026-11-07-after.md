# Benchmark after the speed pass: core-utils vs GNU coreutils 9.7 (2026-11-07)

Same method, machine and inputs as docs/benchmarks/2026-11-07.md (`sh bench/run.sh`,
poop `--duration 1000`, ReleaseFast stripped, `LC_ALL=C`). Ratios are ours / GNU; below
1.00 means ours is better. Wall time on this WSL2 machine moves by up to 2x between runs;
read cycles and instructions first.

## What changed since the first run

| Case | Cycles before | Cycles after | Change |
|---|---|---|---|
| `wc -l` | 38.54 | 0.75 | newlines counted with a 32-byte vector loop; `wc -c` uses the file size |
| `seq 1 2000000` | 5.75 | 1.21 | 64-bit integers and a two-digits-at-a-time formatter for the common case |
| `cat -n` | 4.47 | 0.46 | whole runs copied instead of byte-at-a-time; no format machinery for the line number |
| `tac` | 3.79 (RSS 3.84) | 0.29 (RSS 1.01) | regular files read backwards in 64 KiB windows; vector newline search |
| `tail -n 200000` | 2.49 | 0.78 | vector backward newline search |
| `tr a-z A-Z` | 5.85 | 1.58 | in-place translate and one write per chunk |
| `sort -f` | 2.64 | 1.40 | keys folded once per line, then compared as bytes |
| `sort -g -k4,4` | 1.98 | 0.96 | floats parsed once per line, exact 64-bit prefix |
| `sort -c` | 1.38 (RSS 5.15) | 0.92 (RSS 1.01) | streaming, one line in memory |
| `sort -m` | 1.00 (RSS 10.65) | 0.75 (RSS 1.01) | streaming k-way merge |

Behaviour fixes found by the new tests along the way: `cat -E` now shows a carriage return
before a newline as `^M` (GNU 9.7), and `wc` prints a zero line for a directory operand.

## Still behind GNU

- `wc` and `wc -w` (1.2x cycles): the per-byte word/char state machine.
- `tr a-z A-Z` (1.6x cycles): one table lookup per byte; GNU's loop is faster here.
- `sort -f` and `sort -k1,1` (1.4x cycles): ties on the 8-byte prefix fall back to a
  lookup through two tables.
- `seq` integers (1.2x), `unexpand -a` (1.3x), `fold` (1.1x).
- `tsort` memory (2.3x; it is 1.8x faster in cycles).
- Binary size: 3x to 10x GNU's (unchanged; not part of this pass).
