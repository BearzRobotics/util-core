# Benchmark: util-core diff and cmp vs GNU diffutils 3.12 (2026-11-20)

Method: `/stuff/tmp/claude/bench.py` style harness (median wall time of 3 to 7 runs
with `wait4` for the peak resident set), `LC_ALL=C`, output to `/dev/null`, GNU from
`/usr/bin` (diffutils 3.12), ours built with `-Dmode=standalone`. `crap`/`poop`
could not read the hardware counters on this machine (`perf_event_paranoid=4`), so
cycles and instructions are not reported; wall time and RSS only. The output of
every compared pair was checked byte-identical to GNU's.

Inputs (generated, about 40 byte lines of random words): `1m`, `10m`, `100m` files with
about 10 changes (few), 2% of the lines edited (many), and no common line (all);
`lowv` (400000 lines from 20 distinct values), `midv` (2000 values), `long`
(20000 lines of 100 to 3000 bytes), each with 6% edits and fully shuffled.

All numbers are ours / GNU (below 1.00 is better for us). Machine: 12 logical CPUs, Linux 7.0.

| case | ReleaseFast wall | ReleaseSafe wall | ReleaseSafe RSS (ours / GNU MB) |
|---|---|---|---|
| diff 1m few / many / all | 1.13 / 1.26 / 1.28 | 1.60 / 1.58 / 1.46 | 13 / 13 |
| diff 10m few / many / all | 1.09 / 1.22 / 1.23 | 1.45 / 1.59 / 1.49 | 45-59 / 38-48 |
| diff 100m few / many / all | 0.82 / 0.92 / 0.91 | 1.10 / 1.19 / 1.12 | 512-542 / 399-479 |
| diff lowv, 6% edits | 1.05 | 1.21 | 38 / 33 |
| diff lowv, shuffled | 1.15 | 1.29 | 41 / 39 |
| diff midv, 6% edits | 1.06 | 1.25 | 40 / 35 |
| diff midv, shuffled | 1.13 | 1.29 | 39 / 34 |
| diff long, edits / shuffled | 1.44 / 1.14 | 1.66 / 1.33 | 62 / 66-70 |
| diff -u 100m many | 0.96 | 1.09 | 520 / 415 |
| diff -q 100m many | 0.83 | 0.64 | 13 / 13 |
| cmp 100m identical copy | 1.01 | 1.41 | 13 / 13 |
| cmp 100m differ near the end | 1.01 | 1.41 | 13 / 13 |

The 1 MB rows are 5 to 10 ms process runs, dominated by start-up. Memory is linear in
the input (the line tables plus two copies of the text); files over 1 GiB are refused.

What changed: the inner snake loop of the divide-and-conquer search runs without
safety checks (the indices are bounded by the algorithm), which took the hard cases from
about 2.5 times GNU's time to about 1.1 to 1.3; `diff -q` on regular files compares blocks and stops at
the first difference (or at a size difference) instead of building the line tables.
