# Benchmark: core-utils vs GNU coreutils 9.7 (2026-11-07)

Method: `sh bench/run.sh` (see bench/README.md), poop with `--duration 1000`, our
binaries built with `-Doptimize=ReleaseFast` (stripped), GNU from `/usr/bin`
(Ubuntu `gnu-coreutils` 9.7-3ubuntu2.1, dynamically linked), `LC_ALL=C`.
Machine: AMD Ryzen 5 4600H with Radeon Graphics, 12 logical CPUs, WSL2, Linux 6.18.54.1-microsoft-standard-WSL2.
Inputs: 300 000-line text/CSV/tab files (about 12 MB), a 200 000-edge graph.

All numbers are **ours / GNU**; below 1.00 means ours is better. Wall time on this
machine moves by up to 2x between runs, so read cycles and instructions first
and treat wall ratios within about 20% as noise. Commands that read only
standard input (`tee`, `tr`) run through `sh bench/stdin.sh`, which adds the same
shell cost to both sides and compresses their ratios toward 1.

## Findings, worst first

1. **`wc -l`: 38x cycles, 84x instructions.** GNU counts newlines with a
   vectorised memchr-style loop; ours does not. (`wc` and `wc -w` are at parity.)
2. **`seq 1 2000000`: 5x.** Integer formatting path; the float variant
   (`seq 1 0.5 400000`) is 6x faster than GNU, so the integer path is the outlier.
3. **`cat -n`: 4.5x cycles; `tac`: 3.8x cycles and 3.8x memory;
   `tail -n 200000`: 2.5x cycles and 5.5x instructions.**
4. **`tr a-z A-Z`: 5.9x cycles** even with shell dilution; `tr -d` 1.6x.
5. **`sort`:** `-f` 2.6x, `-g` 2.0x, `-k1,1` 1.4x, `-c` 1.4x cycles; `-m` and `-c`
   use 10.7x and 5.2x the memory (whole input is read, see
   docs/compatibility/sort.md). Plain `sort`, `-u`, `-r` are at parity in
   cycles; `-n` keys are 3x better.
6. **Binary size: 3x to 10x larger than GNU** (even `true` is 236 KB against
   35 KB). GNU's figures exclude the shared libc it loads; ours are static.
   A large part is runtime and formatting code common to every binary, so this is
   a build-configuration question before it is a per-command one.

## Where ours is ahead

`head` (0.5x cycles, 0.13x instructions), `cut`, `paste`, `uniq`, `nl`, `comm`,
`tsort` (0.4x cycles), `mkdir`, `seq` with a step, `sort -n`, and process
start-up for every trivial command (about 0.27x cycles, because a static binary
skips the dynamic loader).
